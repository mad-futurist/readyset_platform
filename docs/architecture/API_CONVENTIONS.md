# API conventions

- Base path: `/api/v1`.
- Resources use plural kebab-free nouns; nested routes express ownership (`/documents/{id}/versions`).
- UUIDs are lowercase canonical strings. Timestamps are UTC RFC 3339 values.
- Auth uses an HttpOnly opaque session cookie. Mutations also send `X-CSRF-Token`. `X-ReadySet-Organization` selects among verified memberships; it never proves membership.
- Collection responses use `{items, page, page_size, total}` with one-based pages and bounded page size. Stable ordering includes an ID tie-breaker.
- Errors use `{error: {code, message, details?, request_id?}}`. Validation returns `422`; unauthenticated `401`; visible-but-forbidden `403`; absent/cross-tenant `404`; conflict `409`; oversized upload `413`; unsupported media `415`.
- Create operations return `201`; delete/archive returns `204`; downloads return streaming responses with safe `Content-Disposition`.
- `Idempotency-Key` is required for invitation resend and will be required for future direct-upload completion. Ordinary UUID-keyed updates are naturally retryable only when documented.
- Document upload is multipart API-proxied in M1. It creates document metadata and version 1 atomically with compensating object deletion on database failure. New version upload is a separate endpoint. Lifecycle is `PENDING_UPLOAD`, `UPLOADED`, `PROCESSING`, `READY`, `FAILED`; M1 stops at `UPLOADED`.
- OpenAPI generated by FastAPI is the source contract. `packages/api-client` contains a generation script and a checked-in thin generated-types placeholder until CI generation is wired to a running API; frontend code must not import ORM models.
- Breaking changes require `/api/v2`; additive response fields and endpoints remain within v1.
- Authentication endpoints never disclose whether an email exists during reset. Login uses a generic failure.
