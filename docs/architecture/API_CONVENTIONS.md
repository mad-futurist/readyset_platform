# API conventions

- Base path: `/api/v1`.
- Resources use plural kebab-free nouns; nested routes express ownership (`/documents/{id}/versions`).
- UUIDs are lowercase canonical strings. Timestamps are UTC RFC 3339 values.
- Auth uses an HttpOnly opaque session cookie. Mutations also send `X-CSRF-Token`. `X-ReadySet-Organization` selects among verified memberships; it never proves membership.
- Documents, people, teams, and audit events use typed `{items, page, page_size, total}` responses with one-based pages, bounded page size, and an ID ordering tie-breaker. Organization memberships, document versions/access grants, and team members remain bounded arrays in M1.
- Errors use `{error: {code, message, details?, request_id?}}`. Validation returns `422`; unauthenticated `401`; visible-but-forbidden `403`; absent/cross-tenant `404`; conflict `409`; oversized upload `413`; unsupported media `415`.
- Create operations return `201`; delete/archive returns `204`; downloads return streaming responses with safe `Content-Disposition`.
- Posting an invitation for an email that already has a pending invitation atomically reissues that invitation: the same invitation row receives a new one-time token, role, inviter, and expiry. No generic `Idempotency-Key` contract exists in M1.
- Document upload is multipart API-proxied in M1. It creates document metadata and version 1 atomically with compensating object deletion on database failure. New version upload is a separate endpoint. Lifecycle is `PENDING_UPLOAD`, `UPLOADED`, `PROCESSING`, `READY`, `FAILED`; M1 stops at `UPLOADED`.
- OpenAPI generated by FastAPI is the source contract. `apps/api/scripts/export_openapi.py` deterministically exports the checked-in schema, `packages/api-client` generates TypeScript declarations, the frontend transport uses those generated component types, and CI rejects drift in either generated artifact. Frontend code never imports ORM models.
- Breaking changes require `/api/v2`; additive response fields and endpoints remain within v1.
- Authentication endpoints never disclose whether an email exists during reset. Login uses a generic failure.
- Registration and invitation persistence is authoritative before synchronous email delivery. Their responses carry `delivery_status` where disclosure is safe; reset and verification-resend keep delivery/account state undisclosed.
- `/livez` performs no dependency I/O. `/readyz` reports only aggregate readiness after checking required database, storage, limiter, and scanner dependencies.
